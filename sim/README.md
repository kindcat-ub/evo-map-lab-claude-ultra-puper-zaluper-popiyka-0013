# sim: симуляция мира автора

Генератор правдоподобного выдуманного источника для Last Drop. Не заглушки, а мир: проекты с историей, решения и их пересмотры, тупики, паузы, связи между проектами, медиа и манга с хотспотами. Всё строится по правилам из seed и детерминированно: один seed даёт побайтово один и тот же источник и те же файлы медиа.

Реальных проектов, людей и продуктов здесь нет и не будет. Словарь (`src/lexicon.ts`) — выдуманные кодовые имена, архетипы и персоны.

## Запуск

```sh
node sim/src/cli.ts --seed 42 --out sim/out      # Node 22.18+, без зависимостей
node contracts/src/cli.ts validate sim/out        # проверка контрактом
cd sim && npm test                                # детерминизм, покрытие сценариев, round-trip
```

Опции: `--projects` (от 5, по умолчанию 7), `--chapters` (3), `--years` (3), `--until` (последний день истории, `2026-10-01`).

Из кода (в том числе в браузере, без node-зависимостей): `generate({ seed })` из `src/generate.ts` возвращает `{ snapshot, media, author }`. `snapshot` — это `Snapshot` из `contracts`, `media` — список файлов, которые рендерит только CLI.

## Что на выходе

Папка в формате `contracts/src/fs-store.ts`: `source.json`, `project/`, `update/`, `research/`, `artifact/`, `chapter/`, `relations.json`, `media/` с настоящими файлами (PNG-картинки и страницы манги, WAV-наброски, Markdown-журналы экспериментов). Плюс `sim.json`: seed, опции, выдуманный автор и какие записи подтверждают каждый сценарий. `sim.json` не часть источника.

## Как устроен мир

- **Архетипы проектов**: приёмник, инструмент для заметок, альбом, игра, исследование, инсталляция. У каждого свои узлы (части), у узла свои взаимоисключающие варианты и свои поломки, поэтому решение «драм-машина вместо живых барабанов» не смешивается с поломкой «перегрев».
- **Арка проекта**: исходный вопрос → старт → случайная последовательность событий (работа, веха, решение, открытие, вопрос, эксперимент, тупик, поломка, выпуск) с причинными связями. Решение по уже решённому узлу всегда пересмотр (`supersedes`). Тупик бьёт по живому решению. Поломка либо вызвана решением (`caused_by`), либо причина неизвестна, и тогда причина не выдумывается, а появляется открытый вопрос о ней.
- **Роли**: пять проектов получают роли, чтобы межпроектные сценарии гарантированно случились: донор тупика, получатель (ему же событие жизни ставит паузу), брошенный, влившийся, принявший слияние.
- **Внутренние события → контракт**: старт, пауза, возврат, брошен, слит — это `note` с `status`; выпуск и веха — `milestone`; эксперимент и поломка — `note`; событие жизни — `Update` без `project`. Слияние по правилу контракта: последний `Update` со `status: done` и связь `dst derived_from src`.
- **Манга**: главы — вольный пересказ проектов (`summary` прямо говорит, что это интерпретация), связаны с событиями через `derived_from`. Страница — картинка и кадры-регионы с литературным текстом. Хотспот `{ icon, target }` ведёт на событие, проект, артефакт или внешний URL. Имена иконок — стартовый набор для фронта: `question`, `decision`, `deadend`, `project`, `music`, `link`, `doc`, `image`.

## Обязательные сценарии

`src/validate.ts` проверяет любой `Snapshot` поверх `validateSnapshot` из контрактов: время не идёт назад по причинным связям, после `dropped`/`done` в проекте ничего не происходит, и каждый сценарий встречается хотя бы раз.

| Сценарий | Что это |
|---|---|
| decision, revision | решение и его пересмотр, старое остаётся в истории |
| deadend, cross-project-unlock | тупик; тупик в одном проекте решил проблему в другом |
| open-question, answered-question | вопрос без ответа и вопрос с ответом |
| unknown-cause | событие без `caused_by`, о нём открытый вопрос |
| pause-resume, life-pause, still-paused | пауза и возврат; пауза из-за события жизни; пауза до сих пор |
| dropped, merge | брошенный проект; проект влился в другой |
| research-concluded, research-open | исследование с выводом и без, с неизвестными |
| month-date, year-date | дата до месяца; только год |
| missing-en | нет английского текста |
| draft | запись не прошла проверку, публичным проекциям не видна |
| media-local, media-url | файл в хранилище; внешняя ссылка |
| hotspot-entity, hotspot-artifact, hotspot-url | хотспот на событие или проект, на артефакт, на URL |

Тест гоняет 60 seed'ов с разным числом проектов и глав, каждый должен пройти контракт и покрыть все сценарии.
