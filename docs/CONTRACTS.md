# Контракты данных Last Drop

Статус: **черновик на ревью**, схема v1. Код: [`contracts/`](../contracts).

## Правило, из которого всё следует

Один источник, много преобразований. Источник хранит факты. Главная, страница проекта, лента, ридер манги и будущая Evolution Map его только читают и ничего не пишут обратно. В источник попадает уже проверенный материал: ревью и приватность Валентин делает руками до записи, система этим не занимается.

Реальных проектов Валентина в репо нет и не будет. Тесты гоняются на маленьком выдуманном мире, разработка — на симуляции (`sim/`).

```
запись автора ──► write() ──► validateSnapshot ──► SourceStore.commit
                                                     │  (память / папка / SQL)
                                                     ▼
                                                  Snapshot ──► publicView ──► проекции ──► HTTP или статика ──► фронт
```

## Сущности

Новых сущностей нет, только то, что согласовано на карте сущностей.

| Вид | Что это | Ключевые поля |
|---|---|---|
| `project` | Проект, в том числе железка | `title`, `summary`, `body`, `started`, `question` → исходный вопрос, `tags` |
| `update` | Любое значимое событие. Без `project` — событие жизни | `date`, `type`, `status?`, `title`, `body` |
| `research` | Гипотеза → проверка | `question`, `hypothesis`, `experiment`, `observations`, `conclusion`, `unknowns` |
| `artifact` | Медиа или любой файл/ссылка. Без типа и без перечня форматов | `ref` (ключ файла или URL), `mime?`, `title?` |
| `chapter` | Глава манги. Страницы и кадры вложены | `number`, `title`, `pages[].panels[]` |
| связь | `from → to` + тип, в том числе между проектами | `{ from, type, to, note? }` |

Общий слой у всех:

- **ID** `kind:key`, key — `[a-z0-9][a-z0-9.-]*`, не зависит от языка и заголовка, не меняется.
- **Текст** `{ ru?, en? }`, языки равноправны, нужен хотя бы один. Markdown допустим.
- **Дата** с честной точностью: `2026`, `2026-09`, `2026-09-07` или ISO с временем. Сортируется как строка.
- **Публикация** `visibility: draft | published`. Draft не виден ни одной публичной проекции. Скрытый проект прячет все свои update, research и artifact, а заодно связи и хотспоты, которые на них смотрят.

### Update

`type`: `note | question | decision | discovery | deadend | milestone`.

Вопрос — это Update с `type: question`. Он открыт, пока на него не ведёт ни одна связь `answers`.

Прошлое не переписывается. Исправление — это новый Update со связью `supersedes` на старый.

`status` (`active | paused | done | dropped`) — необязательное поле. Оно означает, в каком состоянии проект после этого события.

### Чего в источнике нет намеренно

Всё «текущее» вычисляется проекциями и никуда не пишется:

- **статус проекта** — `status` последнего по дате Update, где он указан; если такого нет, `active`;
- **current state** — последние Update проекта;
- **открытые вопросы**;
- **последняя активность**;
- **фокус на главной** — активные проекты с самой свежей активностью.

Геометрии раскладки, зума и Now-координат тоже нет. Это дело Evolution Map. Исключение — `region` кадра: это геометрия самого рисунка, а не проекции.

### Манга

```
chapter { number, title, date?, pages: [ { image?, panels: [ { region?, image?, animation?, hotspots?: [ { icon, target } ] } ] } ] }
```

- Кадр задаётся либо областью страницы (`region` в долях 0..1), либо отдельной картинкой.
- `animation` — медиа, которое играет по тапу на кадр.
- Хотспот — это ровно `{ icon, target }`. `target` — id объекта источника или http(s) URL. Своего типа у хотспота нет: что за ним стоит, решает цель. Музыка, например, — это artifact с URL, либо сразу URL.
- Картинки страниц и анимации — это `MediaRef` главы, а не отдельные artifact. Иначе на каждую страницу пришлось бы заводить запись в источнике.

### Связи

Набор типов: `caused_by, derived_from, depends_on, blocks, supports, contradicts, refines, supersedes, unlocks, implements, answers, relates_to`.

Это словарь из Engine spec 4.3. `belongs_to` убран, потому что принадлежность задаёт поле `project`. Добавлены два типа: `answers` закрывает вопрос, `relates_to` означает просто «связано».

Правила:

- `answers` ведёт только в question;
- `supersedes` связывает объекты одного вида;
- связь не может указывать сама на себя.

## Хранилище за портом

```ts
interface SourceStore {
  load(): Promise<Snapshot>;                                  // весь источник на ревизии N
  commit(base: number, ops: WriteOp[], next: Snapshot): Promise<void>;
}
```

Хранилище глупое. Правила живут в `write()`, который делает четыре шага:

1. сверяет ревизию;
2. применяет операции;
3. валидирует результат целиком;
4. отдаёт его хранилищу.

Адаптер получает и дельту (`ops`), и итог (`next`), поэтому SQL может писать точечно, а файлы — перезаписывать только затронутое.

`Snapshot` грузится целиком. Это личный сайт, а не соцсеть: тысячи записей, не миллионы. Когда упрёмся, проекции переедут на запросы, а контракт не изменится.

Сейчас есть два адаптера:

- `MemoryStore` — для тестов;
- `FsStore` — источник как папка. Это же **формат обмена** с генератором:

```
<root>/source.json          { "schema": 1, "revision": N }
<root>/<kind>/<key>.json    одна запись = один файл, руками редактируется
<root>/relations.json       Relation[]
<root>/media/…              файлы для относительных MediaRef
```

`MediaRef` — это либо ключ файла (`media/vasya5123.jpg`), либо внешний URL. Фронт превращает ключ в адрес через `mediaUrl(ref, base)`.

## Запись

```ts
type WriteOp =
  | { op: 'put'; entity }            // создать или заменить целиком
  | { op: 'delete'; id }
  | { op: 'link'; relation }
  | { op: 'unlink'; from, type, to };

write(store, { base: N, ops }) → { revision: N + 1 }
```

- Пачка операций атомарна: либо ложится вся, либо ничего.
- Если `base` устарела, это конфликт (409), и ничего не записано.
- Невалидный итог, например висячая ссылка после удаления, — отказ (422) со списком проблем.
- Пишет только автор. Публичной записи в MVP нет.

## API бэк ↔ фронт

Префикс `/api/v1`. Каждый путь существует в двух видах:

- **live** — сервер считает ответ на лету;
- **static** — тот же JSON, заранее выгруженный файлом `<путь>.json` командой `cli.ts export`.

Фронту всё равно, какой из них ему отдают. Двоеточий в путях нет, чтобы статика жила на любом хостинге.

| Путь | Ответ | Кому |
|---|---|---|
| `GET /home` | `HomeView`: фокус, проекты, недавнее, открытые вопросы, последняя глава | главная |
| `GET /projects` | `ProjectCard[]` | Projects |
| `GET /projects/:key` | `ProjectView`: проект, вычисленный статус, current, вопросы, все Update, research, artifacts, связи наружу | страница проекта |
| `GET /activity?project&type&before&limit` | `ActivityView`, курсорная пагинация | Activity |
| `GET /manga`, `GET /manga/:key` | `ChapterCard[]`, `ChapterView`: хотспоты уже с карточками целей, prev/next | ридер |
| `GET /resolve/:kind/:key` | `Card` любого объекта | превью хотспота, ссылки |
| `GET /graph`, `GET /graph/:key` | `GraphView`: узлы-карточки и связи без геометрии | Evolution Map |
| `GET /source`, `GET /source/:id` | весь источник, включая draft | автор, Bearer |
| `POST /source` | `{ base, ops }` → `{ revision }` | автор, Bearer |
| `PUT /media?key=…` | байты → `{ ref }` | автор, Bearer |

- Все публичные ответы строятся по `publicView`: draft туда не попадает физически.
- Live-ответы помечаются `ETag: "r<ревизия>"`.
- Тексты отдаются на обоих языках. Язык выбирает фронт через `pick(text, lang)`: если нужного языка нет, отдаётся другой с честной пометкой.

## Как этим пользоваться

```sh
cd contracts && npm i
npm test                                   # контракт на выдуманном мире
node src/cli.ts validate <папка-источник>  # генератор гоняет свой вывод через это
node src/cli.ts export <папка> <out>       # статика для сайта
LASTDROP_TOKEN=… node src/cli.ts serve <папка> 8787
```

TypeScript без рантайм-зависимостей. Node ≥ 22.18 запускает `.ts` напрямую, Vite и SvelteKit импортируют `contracts/src/index.ts` как есть. Адаптеры на `node:fs` и `node:http` лежат отдельно, в браузерный бандл они не попадают.

## Открыто, решает Валентин

1. **Позиция иконки хотспота.** Сейчас её нет: хотспот — это строго `{ icon, target }`, и фронт рисует иконки полосой у кадра. Если иконки нужны в конкретной точке кадра, добавится `at: [x, y]`.
2. **Текст манги RU/EN.** Сейчас реплики живут внутри картинки. Если нужен переводимый текст поверх кадра, это ещё одно поле кадра.
3. **Фокус на главной.** Сейчас он вычисляется: самые свежие активные проекты. Если Валентин хочет выбирать фокус руками, это одно поле, но тогда это хранимое «текущее».
4. **Principles и RESPOND** из доков Last Drop сюда не вошли, их нет в согласованном списке.
